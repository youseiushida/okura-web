# AI の会話（チャット）とカード

## 考え方

- 会話の **文章** と、データベースに入れる内容を出す **カード** を分ける。カードは会話の吹き出しとは別の見た目
  （太い枠・「この内容で登録します」・日本語の欄名と値・［登録］［直す］［やめる］）。
- AI は HTML や画面のコードを作らない。AI が呼んだ道具の結果（提案の ID・選択肢・家計簿の登録待ち）から、
  アプリが決まった部品（カタログ）だけを描く。Google の A2UI と同じ考え方（エージェントは「出したい部品」を言うだけ、描くのはクライアント）。
- 登録は人が押したときだけ（AGENTS.md 4）。カードのボタンは画面のセッションから、既存の提案の確定・取消しの API を呼ぶ。
  押した結果は会話に「（画面で：登録しました…）」として残し、AI は次の返事でそれを知る（LLM は呼ばない）。
- 提案の前に、記録をデータベースの写しに入れて確かめる（`tools.check_records`。本物は変えない）。合わなければ問題を AI に返し、AI が直して提案し直す。
  日付を when の外に書くなど、よくある形の間違いは `tools.normalize_record` で直す。

## カードの種類

| 部品 | 出す道具 | 中身 |
|---|---|---|
| 登録の確認（1件） | `propose_record`・`propose_judgment`・`propose_forecast`・`propose_person`（家族の追加：名前と生年月日）・`propose_change`（記録の取消し・訂正。押すと追記される）・`propose_records`（1件） | 記録の種類・日本語の欄と値・原本へのリンク・AI の説明。［登録］［直す］［やめる］ |
| まとめて登録 | `propose_records`（2件以上） | 行ごとのチェック。行を押すと中身を見て直せる。［○件を登録］ |
| 画面への入口 | `show_screen` | 行き先は決まった一覧からだけ（AI は URL を作らない）。押すとその画面に移る |
| 質問 | `ask_user` | 質問と選択肢のボタン。押すと答えが次のメッセージになる（AI はそこで返事を止める） |
| 家計簿 | `propose_book_entries` | 家計簿の登録待ちに入れた件数。［登録待ちを開く］ |

## 添付・貼り付け

- 📎・画像の貼り付け・ドラッグで、写真（JPEG・PNG・WebP・GIF）・PDF・Excel（.xlsx）・CSV・TSV・テキストを添付できる。
  添付は原本の保管庫に保存し（sha256）、登録した記録と結びつく。
- LLM への渡し方（OpenAI 互換の Chat Completions の形の中で）：画像は `image_url`（data URL）、PDF は `file`（`file_data` の data URL。
  cliproxy 経由で Claude が読めることを確かめた）、Excel・CSV は `okura_web/sheets.py` で表の文字にして `text`。
- Excel は標準ライブラリで zip の中の XML を読むだけ。マクロ・外部リンクは実行しない。大きさ・ファイル数・行数の上限、DTD・実体の定義を含む XML は読まない。
- 外部の AI のとき：写真・表は伏せ字にできないので、添付の持ち主が「外部の AI」に同意している原本だけを送る。送る前に画面に注意を出す。

## 見た目

- 文章は Markdown（太字・見出し・箇条書き・表・コード）を HTML を使わずに描く（`chat.js` の `md`）。
- 道具の呼び出しは「家族の状態・計算結果を見ました」の1行にまとめる（押すと順番を出す）。
- 文章の中の人の ID・英字の内部の名前は、表示名・日本語に直して出す（`humanize`）。
- スマホは全画面、PC は右の枠。入力欄は下に固定。
